# 2026-08-03 更新

## 简化设备解析

- 仅支持 `--device cpu` 和 `--device cuda`，默认使用 CPU。
- `cuda` 内部解析为 `cuda:0`，确保设备检查一致。
- `resolve_device_ms` 包含首次 CUDA 可用性检测，因此可能包含一次性的 CUDA 初始化耗时。

## 简化计时输出

- 默认仅输出 `stage1_prepare`、`stage1_run_ms`、`stage2_prepare`、
  `stage2_pose_run_ms`、`stage2_joints_run_ms`、`fitting_total_ms` 和
  `command_total_ms`，单位均为毫秒。
- `fitting_total_ms` 包含各 Stage 的 prepare/run 和 pipeline 编排开销；
  `command_total_ms` 还包含 context 构建、结果整理及首次 JSON/NPZ 保存。
- 仅在 `--profile_timing` 下输出 context、prepare、LM 和保存阶段的分层明细，
  并显式记录包含关系。
- 移除重复的 cache 展开计时；Stage 内部 `wall_time_ms` 仅在 profile 模式输出。
- timing JSON 的初始化集中到 `stage_timing.build_pipeline_timing()`，不再内联于
  `run_production_pipeline()`。
- 最终 objective 分项检查移至 validation；production 不再重复计算或输出
  `beta.lm.breakdown`，可通过 `run.py objective-breakdown` 单独验证。
- 删除 production JSON 中始终为未执行状态的 `gate_c_verdict`；真实 Gate C 检查
  继续保留在 validation。

## 清理 production L-BFGS 兼容结构

- Production 仅保留 LM，删除固定为空的 L-BFGS result、handoff、JSON 和 NPZ 字段。
- 删除 production `SolverConfig` 中的 L-BFGS 参数及可视化中的 solver 选择。
- L-BFGS oracle、结果类型和迭代参数移入 validation，不影响 LM/L-BFGS 对齐验证。
